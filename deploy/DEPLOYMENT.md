# Deployment — Stationery Management System

Two deployment paths depending on the setup:

| Path | When to use | What you need |
|------|-------------|---------------|
| **[A] start.bat — run from source](#a-startbat--run-from-source)** | Dev machine or any laptop with Node + Python already installed | Node.js, Python 3.x |
| **[B] Windows Service (always-on LAN server)](#b-windows-service--always-on-lan-server)** | Receptionist laptop that must auto-start at boot, survive reboots, serve the whole network | Nothing — PyInstaller bundle ships its own Python |

---

## A. start.bat — run from source

The simplest path. One double-click does everything: installs dependencies on
first run, creates config, and starts both servers.

### Requirements

- Python 3.10+ (`python --version` to check)
- Node.js 18+ (`node --version` to check)

### First run

Double-click **`start.bat`** in the project root (or run it from a terminal).

It does the following automatically:

1. Creates `backend\venv` (Python virtual environment)
2. Installs Python packages from `backend\requirements.txt`
3. Runs `npm install` in `frontend\`
4. Writes **`backend\.env`** with a random `SECRET_KEY` and default credentials
5. Opens two windows: Flask backend on `:5000`, Vite frontend on `:3000`

Steps 1–4 are skipped on subsequent runs (sentinels already present).

### Default credentials (first run)

| Account | Username | Default password |
|---------|----------|-----------------|
| Admin | `invinder_kaur` | `admin123` |
| Guest | `guest` | `guest123` |

Credentials and secret key are stored in **`backend\.env`** (git-ignored).
Edit that file to change passwords, then add `RESET_PASSWORDS=1` and run
`start.bat` once — the accounts update on startup. Remove `RESET_PASSWORDS=1`
afterwards.

### URLs

| Service | URL |
|---------|-----|
| Frontend (React) | http://localhost:3000 |
| Backend (Flask API) | http://localhost:5000 |

### Stopping

Close the two cmd windows that `start.bat` opened.

### `backend\.env` reference

```
SECRET_KEY=<auto-generated 64-char hex>
ADMIN_PASSWORD=admin123
GUEST_PASSWORD=guest123
SEED_DEMO=0
```

To seed demo data for testing, set `SEED_DEMO=1` and restart.

## B. Windows Service — always-on LAN server

Run the whole system from the receptionist's Windows laptop and serve it to
everyone on the local network. The laptop needs **nothing installed** — not even
Python. The server auto-starts at boot, keeps running with the lid closed,
survives power cuts, and restarts itself if it ever stops.

```
   LAN clients (phones / PCs)            Receptionist laptop
   http://<laptop-ip>:8080   ───────▶   Windows Service "StationeryServer"
                                           └─ Waitress  ─┬─  /api/*   (Flask backend)
                                                         └─  /*       (React SPA)
                                           Data: C:\StationeryApp\data\stationary.db
```

### How it works

- **One process, one port.** The React app is pre-built to static files and
  served same-origin by the Python backend via Waitress. The frontend calls
  `/api` with relative paths, so every LAN client just works — no CORS, no
  per-client config.
- **No Python on the laptop.** PyInstaller packages the backend + bundled
  frontend into a self-contained Windows folder. Copy that folder to the laptop
  and run it.
- **Always-on.** Installed as a Windows Service (via NSSM) set to auto-start
  at boot and auto-restart on exit. The database lives in a separate folder so
  restarts and updates never lose data.

### Step 1 — Build (on a dev machine with Node + Python)

```
deploy\build.bat
```

Builds the frontend, installs backend deps, runs the test suite (aborts on
failure), and packages with PyInstaller. Output:

```
backend\dist\StationeryServer\        ← copy this whole folder to the laptop
```

> Build on a machine with the **same Windows architecture (64-bit)** as the
> laptop.

### Step 2 — Install on the receptionist laptop

1. Create `C:\Install\` and put in it:
   - `StationeryServer\` (from Step 1)
   - `install-service.bat`, `uninstall-service.bat`, `set-service-env.ps1` (from `deploy\`)
   - `nssm.exe` (64-bit build from https://nssm.cc/download)
2. **Right-click `install-service.bat` → Run as administrator.**
3. When prompted, enter the ADMIN and GUEST passwords (hidden, confirmed twice).

The installer automatically:

| Step | What it does |
|------|--------------|
| Copy app to `C:\StationeryApp\app` | keeps data separate for safe updates |
| `powercfg` never-sleep + lid close = Do nothing | laptop serves with the lid shut |
| Firewall rule for TCP 8080 (private/domain) | lets LAN clients connect |
| NSSM service, auto-start at boot, auto-restart on exit | starts without login, resumes after crash/power-cut |
| Prompts for ADMIN/GUEST passwords + generates SECRET_KEY | real credentials set at install |

At the end it prints the URL to hand out (e.g. `http://192.168.1.50:8080`).

> **Reinstalling over an existing database?** The installer detects it and asks
> whether to update the accounts to the new passwords. Data is kept either way.

### Step 3 — Make the address stable

DHCP can change the laptop's IP. Options:

- **Best — DHCP reservation:** bind the laptop's MAC to a fixed IP in the
  router. URL stays constant forever.
- **Static IP** on the laptop's network adapter.
- **Prefer wired Ethernet** — more stable than Wi-Fi when the lid is closed.
- *(Optional)* Serve on port 80 so the URL is just `http://<ip>`. Change `PORT`
  in `install-service.bat` to `80` and reinstall.

Print a card / QR for staff (the app has a QR display page at
`/receptionist` → "Show QR code").

### Day-to-day operations

- **Logs:** `C:\StationeryApp\logs\out.log` and `err.log`
- **Restart:** `nssm restart StationeryServer` (admin) or via `services.msc`
- **Backups:** `deploy\backup-db.bat` keeps the last 30 daily copies. Schedule it:
  ```
  schtasks /create /tn "StationeryBackup" /tr "C:\StationeryApp\app\backup-db.bat" /sc daily /st 20:00 /ru SYSTEM
  ```
- **Update to a new version:**
  ```
  nssm stop StationeryServer
  robocopy <new>\StationeryServer C:\StationeryApp\app /MIR
  nssm start StationeryServer
  ```
  The database in `C:\StationeryApp\data` is untouched.
- **Uninstall:** run `uninstall-service.bat` as admin (database kept).

### Changing passwords after install

Re-run `install-service.bat`; it detects the existing database and asks whether
to update accounts to the new passwords (`RESET_PASSWORDS=1`). Data is preserved.

### Runtime environment variables

| Variable | Default | Purpose |
|----------|---------|---------|
| `PORT` | `8080` | LAN port |
| `STATIONERY_DATA_DIR` | `C:\StationeryApp\data` | folder holding `stationary.db` |
| `SECRET_KEY` | *(random, set at install)* | Flask session signing key |
| `SEED_DEMO` | `0` | `1` seeds demo data (dev only) |
| `ADMIN_PASSWORD` / `GUEST_PASSWORD` | *(set at install)* | seeded account passwords |
| `RESET_PASSWORDS` | `0` | `1` updates existing account passwords on next boot |

### Quick verification after install

From another device on the same network, open `http://<laptop-ip>:8080`:

- Close the laptop lid → page still loads from the other device.
- Reboot the laptop (don't log in) → within ~30s the page loads again.
- `nssm stop StationeryServer` then wait → NSSM restarts it automatically.

If a check fails, see `C:\StationeryApp\logs\err.log`.

### Security notes

- Passwords are never hardcoded; set at install time.
- Plain HTTP on the LAN is fine for an internal network. Do **not** port-forward
  to the internet. For external access use a VPN or a reverse proxy with TLS.
- `SEED_DEMO=0` (set by the installer) keeps demo data out of production.
